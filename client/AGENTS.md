# AGENTS.md

SiftFlow client — Vite 8 + React 19 (React Compiler) + Tailwind 4 + HeroUI v3 SPA built with Feature-Sliced Design. It talks to the Nest/GraphQL API in `../server` over urql. Docs: [DESIGN.md](DESIGN.md) (visual system), [docs/graphql-cache.md](docs/graphql-cache.md) (cache), [.heroui-docs/react](.heroui-docs/react) (HeroUI v3).

## Commands

All of these run from `client/` with bun:

```sh
bun run dev            # Vite dev server on :3000
bun run build          # tsc -b && vite build — the real type/compile check
bun run lint           # oxlint
bun run format         # oxfmt (sorted imports, sorted Tailwind classes)
bun run codegen        # graphql-codegen, one-off
bun run codegen:watch  # graphql-codegen --watch
```

There is no test runner in this package — verify changes with `bun run build` + `bun run lint`.

## Environment

Copy `.env.example` to `.env`. `VITE_BASE_URL` (`http://localhost:5000/graphql`) is required: `src/shared/constants/env.ts` validates it with `@t3-oss/env-core`, so a missing value fails the app at import time, not at the first request.

## Architecture

The project follows Feature-Sliced Design (FSD) architecture.

All new code must follow the existing FSD layer structure and dependency rules. Place features, entities, widgets, pages, shared components, and application-level logic in their appropriate FSD layers.

Do not introduce alternative architectural patterns or bypass FSD layer boundaries without a clear reason.

Use skill: [feature-sliced-design](.agents/skills/feature-sliced-design/SKILL.md). Other repo skills, by task: `frontend-design` (UI), `transitions-dev` (animation snippets), `grill-me` (requirements sharpening).

Layers in `src/`: `app/` (providers, `global.css`, generated route tree), `widgets/` (`authenticated-layout`, the `*-flow` screen slices), `features/` (`auth`, `workspace-form`, `change-member-role`, `remove-workspace-member`), `entities/` (`workspace` — role/status labels, colors, permission rules), `pages/`, `shared/` (`api`, `constants`, `hooks`, `stores`, `ui`, `utils`). Every slice exposes its public API through `index.ts`.

Placement rules:

- `pages/` holds **route files only** — no `-api/`, `-model/`, `-ui/` folders inside `pages/`. The route file composes slices and may keep its own trivial local `RouteComponent`.
- A whole screen (its states, chrome and loaders) lives in `widgets/<name>-flow/` — see `invitation-flow`, `onboarding-flow`, `workspace-members`.
- A user action lives in `features/<action>/` (`api/` documents, `model/` hook, `ui/` control) — including row-level actions such as `change-member-role` and `remove-workspace-member`. A widget composes features and entities; it does not implement their mutations itself.
- Domain data and rules shared by several slices (role labels/colors, `getMemberPermissions`, `getMemberActionErrorMessage`) live in `entities/<entity>`, not in the slice that happens to use them.

Routes are file-based from `src/pages`; `_authenticated.tsx` and `_authenticated/_shell.tsx` are pathless layout routes: the first holds the session guard and workspace loader, the second mounts the app shell, and `onboarding.tsx` deliberately sits outside that shell. `_shell/w.$slug.tsx` resolves the workspace from the slug (redirecting to the first workspace when the slug is unknown) and nests the `w.$slug.dashboard` / `w.$slug.members` screens.

## Code conventions

- **No comments in code** (`//`, `/* */`, JSDoc) unless the user explicitly asked. Code and names should be self-explanatory.
- TypeScript; use `~/` alias over long relative imports. Use `import type` for type-only imports.
- **Never import React types** (`ComponentProps`, `ReactNode`, `CSSProperties`, `PropsWithChildren`, `ComponentType`, etc.) from `'react'`. Use the global `React.*` namespace with **no type import** — e.g. `React.ComponentProps<'div'>`, `React.ReactNode`. Runtime APIs still need normal imports: `import { useState, useMemo } from 'react'`. Never write `import * as React from 'react'` for types only.

  ```ts
  // ✅ good
  export const Input = (props: React.ComponentProps<'input'>) => { ... }

  // ❌ bad
  import type { ComponentProps } from 'react'
  export const Input = (props: ComponentProps<'input'>) => { ... }

  // ❌ bad
  import * as React from 'react'
  ```

- Named exports and arrow components/functions (`export const Component = () => {}`). Local route components may use `function RouteComponent()` — do not rewrite without reason, but follow the primary convention in new shared code.
- **One component per file, named after the file.** A component module exports the component it is named after and nothing else; every further component — a state variant of a screen, a card wrapper, a sub-view — goes into its own file in the same `ui/` segment and is imported. A trivial presentational fragment (a few lines, no hooks, no branching logic) may stay local. "It is only used here" is not a reason to stack a real component on top of another one.
- No default export for app code. Exceptions: required Vite / oxfmt / oxlint config and TanStack Query devtools — not a template for modules.
- Use `??` for fallback only on `null`/`undefined`; do not replace intentional falsy logic with it.
- `erasableSyntaxOnly` is on: no TS `enum`, `namespace` or constructor parameter properties. Use `as const` object maps, and take GraphQL enums from codegen.
- Conditional React render: `condition && <Component />`, never `condition ? <Component /> : null`.
- **Generated files.** Never hand-edit [routeTree.gen.ts](src/app/routeTree.gen.ts) or anything under [src/shared/api/graphql/gql](src/shared/api/graphql/gql).

## Design system

Visual rules live in [DESIGN.md](DESIGN.md): zero radius, hairline borders, flat surfaces, exactly one blue accent, no shadows. Tokens (colors, type scale, motion durations/easings) are declared in [src/app/global.css](src/app/global.css) and consumed as `className` utilities — do not hardcode values in components. Component markup comes from HeroUI v3; read its vendored docs in `.heroui-docs/react` before writing or changing a component.

## Icons

Icons come from [reicon](https://reicon.dev) through the `reicon-react` package. Import the individual icon by name (`import { Home, Kanban } from 'reicon-react'`); each icon renders `currentColor` at 24px by default, so size and color are set with `className` (`size-5`, `text-muted`). Do not add a second icon set and do not hand-draw SVGs.

## GraphQL

The client uses [urql](https://nearform.com/open-source/urql/) with documents typed by [GraphQL Code Generator](https://the-guild.dev/graphql/codegen) (`@graphql-codegen/client-preset`).

- The urql client and the generated `graphql` tag are exposed by the `~/shared/api/graphql` segment. Import from there, never from internal files.
- `UrqlProvider` is wired in [Providers.tsx](src/app/providers/Providers.tsx).

- The schema is read from `../server/src/schema.gql`. Regenerate after any schema or document change:

  ```sh
  bun run codegen        # one-off
  bun run codegen:watch  # watch mode
  ```

- Output goes to `src/shared/api/graphql/gql/`. It is ignored by oxlint/oxfmt and marked `@ts-nocheck` by codegen.
- The client uses a normalized cache (`@urql/exchange-graphcache`), so mutations update cached lists in place instead of triggering a refetch. Read [docs/graphql-cache.md](docs/graphql-cache.md) before adding a mutation that touches cached data — in particular, documents patched by the cache layer must live in `src/shared/api/graphql`.

## Pitfalls

- `../server/src/schema.gql` is generated by the server at boot. After changing a resolver, DTO or entity, start the server once, then run `bun run codegen` here — otherwise codegen works from a stale schema.
- Errors from the API are GraphQL codes mapped to copy in [src/shared/api/graphql/apiError.ts](src/shared/api/graphql/apiError.ts); add a code there instead of rendering a raw server message. Mutations go through `executeGuardedMutation` so an expired session/CSRF token is handled in one place.
- The `_authenticated` loader must not redirect `/onboarding` when the workspace list is empty (it would loop); keep the empty-list branch for that path.
- lefthook (root `lefthook.yml`, covers client and server) runs on commit (`oxlint --fix` + `oxfmt` on staged files) and on push (`tsc -b` in `client/`, `tsc --noEmit -p tsconfig.json` in `server/`). Run `bun run lint`, `bun run format` and `bun run build` before committing, or the hooks will rewrite/fail your commit.
- The client is useless without the API: `bun run dev` talks to the Nest/GraphQL server from `../server` on `:5000`. Start the server first, or every query fails while the UI looks fine.
- **Cache-updating mutations have two sharp edges.** A list subscribed with `requestPolicy: 'network-only'` never receives cache updates — reads that must reflect a mutation need `cache-and-network`. And `cache.updateQuery({ query })` without `variables` silently no-ops on a paginated query: enumerate `cache.inspectFields('Query')` and pass each field's own `arguments`. `cache.invalidate` needs an id (only a bare typename string clears a whole type). Details in [docs/graphql-cache.md](docs/graphql-cache.md).
